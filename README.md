# Hybrid Novel Game Engine - Prototype

Go言語（超高速API）、PHP（データマスタ管理）、HTML5/Vanilla JS（軽量表現層）を融合させた、構造科学的アプローチに基づくハイブリッド型ノベルゲーム・エンジンの最小プロトタイプです。

## 🪐 アーキテクチャ概要（構造設計）

本システムは、「データの可変性（柔軟な運用）」と「実行の不変性（堅牢な配信）」を高次元で両立させるため、以下の3層レイヤー構造を採用しています。

[ライター / 管理者] ──>  ① PHP (マスタ入稿・JSONシリアライズ)
│
▼ [データ連携: scenario.json]
[プレイヤー]         <──>  ② Go API Server (オンメモリ配信・ステート管理)
│
▼ [REST API / CORS]
③ HTML5 / JavaScript (Vanilla JS レンダラー)


1. **データマネジメント層 (PHP)**: シナリオの分岐、テキスト、フラグ制御といった複雑なリレーション構造を高速に構築・管理。
2. **ハイパフォーマンス配信層 (Go)**: 静的マスタを起動時に完全メモリキャッシュ。ディスクI/Oを徹底的に排除し、スパイクアクセスをミリ秒単位で吸収。
3. **プレゼンテーション層 (HTML5/JS)**: 外部依存（ライブラリ）ゼロ。データ駆動型で画面を動的に書き換える軽量なノベルコア。

## 🛠️ ディレクトリ構造

```text
.
├── master_generator.php   # シナリオデータの定義・JSON出力 (PHP)
├── scenario.json          # PHPから書き出され、Goが読み込む中間マスタ (生成物)
├── main.go                # 超高速API / セーブ・ステート管理サーバー (Go)
└── game.html              # ゲーム画面 / 演出・通信駆動レンダラー (HTML/JS)
🚀 起動手順・運行マニュアル
システムを駆動させるには、以下のステップを順番に実行します。

1. シナリオデータの生成 (PHP)
まず、シナリオテキストや分岐フラグを内包したマスタデータをシリアライズします。

Bash
php master_generator.php
実行に成功すると、同階層に scenario.json が出力されます。

2. APIサーバーの常駐化 (Go)
次に、プレイヤーからのリクエスト（シナリオ要求 / セーブ / ロード）を制御するバックエンドを起動します。

Bash
go run main.go
ターミナルに [Go] API Server running on :8080... と表示されれば、防衛ライン（通信待受け）は確立されています。ゲームプレイ中はこのターミナルを閉じないでください。

3. ゲームの実行 (HTML5)
ブラウザで game.html を直接開くか、ローカルのWebサーバー（XAMPP等）経由でアクセスします。

起動時にGoのAPI（:8080/api/scenario）から自動でデータが同期されます。

右上の「SAVE / LOAD」ボタンを押すことで、状態がGoのオンメモリ上に保持・復元されます。

📈 今後の拡張（防衛戦略）
この最小システムは、プロダクション規模の戦闘（大規模開発）に耐えうる拡張性を秘めています。

PHP側の強化: Laravel等のフレームワークを用いて、Webブラウザベースの「ビジュアルシナリオ入稿エディタ」へ拡張。

Go側の強化: プレイヤーのセーブデータの永続化領域を、オンメモリハッシュマップから Redis や PostgreSQL へ換装。

JS側の強化: 演出面のリッチ化のため、フロントエンドの通信ロジックを保持したまま、描画エンジンを PixiJS や Unity (WebGL) へコンポーネント置換。
